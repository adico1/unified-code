# Knowledge continuity and Second Brain synchronization

## Purpose

Unified Code is discussed and published across several independent systems:

```text
repository code and documentation
GitHub issues, pull requests and discussions
adico.tech articles
social publications
Obsidian Second Brain
```

Publishing to one system does not update the others. The Second Brain is a
searchable knowledge projection, not the hidden memory of the repository or an
automatic mirror of GitHub.

## Incident: missed Deterministic AI Pyramid context

On 2026-08-01, a search of the registered Obsidian vaults found no note for the
Deterministic AI Pyramid. The absence of a local result was incorrectly
reported as absence of prior context. Public authority already existed in
[Discussion #2](https://github.com/adico1/unified-code/discussions/2) and its
linked article, which establish the Standard Ten direction of one deterministic
software structure for humans and AI. The newer ownership, stewardship and
liveness layer extends that published direction.

## Root-cause analysis

| Question | Finding |
| --- | --- |
| Why was the public context missed? | Retrieval stopped after searching the local Second Brain. |
| Why was it absent from the Second Brain? | The publication workflow had no knowledge-capture event. |
| Why was there no capture event? | GitHub, WordPress, social channels and Obsidian were treated as unrelated boundaries. |
| Why was the omission silent? | Completion reports did not include knowledge-sync status. |
| Why did absence become a false conclusion? | Search scope and authority scope were not reported separately. |

Contributing conditions:

- Second Brain access is read-only by default and writes require explicit user
  authorization.
- GitHub Discussions are not automatically ingested into registered vaults.
- There was no canonical project note linking the repository, Discussion #2,
  the article, the Atlas and current merge identities.
- Naming differed between `Standard Ten`, `Unified Code`, `Application Atlas`
  and `Deterministic AI Pyramid`, so a narrow exact-term search could not join
  them.

The search tool itself was not the root cause: it correctly reported what was
present in the registered vaults.

## Authority law

```text
public source records the claim
repository records executable engineering truth
Second Brain indexes and connects those authorities
```

The Second Brain must not silently replace public sources or repository
evidence. A knowledge note records source identities, links, status and
distinctions; it does not turn a vision into a proven result.

## Required publication flow

Every completed publication should expose this event chain:

```text
publication.completed
→ knowledge.capture.requested
→ public.authorities.resolved
→ knowledge.note.projected
→ retrieval.index.verified
→ knowledge.sync.completed
```

If the vault is unavailable, read-only, ambiguous or unauthorized, the final
status must be `knowledge.sync.pending` or `knowledge.sync.blocked`. It must
never be silently omitted or reported as complete.

## Canonical knowledge record

A project knowledge record should contain at least:

```text
canonical project identity
record version
claim status: vision | research | implemented | proven | disproven
source URLs and source types
repository commit or merge SHA when applicable
issue, PR and discussion identities
article identity
concise current finding
explicit non-claims
open questions and next evidence
captured_at as evidence, not semantic identity
```

Source content should normally remain at its public authority. The knowledge
record links and summarizes it instead of copying entire discussions, articles
or repositories into the vault.

## Retrieval rule

For project-history questions:

1. Search the Second Brain.
2. Report the exact scope searched.
3. Resolve linked public authorities when the question concerns publication,
   GitHub state or current evidence.
4. Distinguish `not found locally` from `not documented anywhere`.
5. Cite the exact vault note and public source supporting each conclusion.
